# 忆习 · 完整商业版方案

> 用途：当前阶段暂停新功能开发，进入**测试与体验完善**；本文档作为后续把「可验证 MVP」推进到「完整商业版」的路线图与对照清单。  
> 状态基准：2026-08（主闭环已完成；M2 额度/广告/订阅**代码已有、默认关闭**）

---

## 1. 产品定位与版本定义

| 版本 | 定义 | 当前状态 |
|------|------|----------|
| **可验证 MVP** | 用户能独立完成「规划 → 记卡片 → 按遗忘曲线复习」，并可分享/管理计划 | **已达成** |
| **对外运营 v1** | 能过审上架、控 AI 成本、有基础留存触达（额度 + 广告 + 订阅） | 待开 M2 + 审核配置 |
| **完整商业版** | 能稳定赚钱（会员/支付）、有内容壁垒、有运营数据与合规 | 待按本文分阶段建设 |
| **成熟壁垒版** | OCR/判分/多会话等深度体验 + 风控与增长体系 | 长期可选 |

**现阶段建议**：以测试体验为主，修交互与稳定性；商业能力按「对外运营 v1 → 完整商业版」顺序推进，避免一次铺太开。

## 2. 已完成闭环（前期需求已满足）

### 2.1 主业务闭环

```
对话制定目标
  → AI 生成学习计划 + 记忆卡片
  →（可选）上传资料 / PDF 再出题
  → 今日待复习 + SM-2 间隔提交
  → 学习报告
  → 分享得次数 / 邀请奖励（裂变骨架）
  → 计划暂停 / 恢复 / 归档 / 删除
```

### 2.2 能力清单（已实现）

| 模块 | 能力 | 说明文档 / 入口 |
|------|------|----------------|
| 登录身份 | `OPENID` → `ensureUser`，前端不传 `userId` | `docs/setup.md`、`common/auth.js` |
| AI 对话 | 场景引导、触发生成计划 | `pages/chat`、`chat` 云函数 |
| 计划 + 卡片 | 周计划、问答卡片、SRS | `generatePlan`、`common/srs.js` |
| 今日 / 复习 | 到期卡、自评质量 | `getToday`、`review` |
| 资料出题 | 文本 / pdf / txt / md；长文头中尾抽样 | `docs/m3-material.md` |
| 计划管理 | 暂停（挂起卡片）、归档、删除连带资料 | `getToday` `managePlan`、`pages/plans` |
| 学习报告 | 连续天数、掌握率、近 7 日、回忆质量 | `docs/m4-report.md`、`pages/report` |
| 分享裂变 | 分享日限领额度；受邀绑定一生一次 | `docs/m2-share.md` |
| 额度/广告/订阅 | **已实现，默认不拦截、入口隐藏** | `docs/m2-setup.md`，`ENFORCE_QUOTA: false` |
| 工程与安全审查 | IDOR、额度原子、计划生成上限、提醒分页等 | `docs/review.md` |

### 2.3 技术底座（后续开发勿破坏）

- 公共逻辑只改 `cloudfunctions/common`，部署前 `node scripts/install-functions.js`
- AI 只走 `common/ai.js`；密钥仅云函数环境变量
- 集合名 / 错误码 / 默认值集中在 `common/constants.js`
- 前端云调用统一 `miniprogram/utils/api.js`
- 编码规范见 `.cursor/rules/coding-standards.mdc`

## 4. 分阶段路线图

### 阶段 A：测试与体验完善（当前阶段）

**目标**：主闭环在真机上稳定、好懂、少报错；不新增大功能。

建议自测清单（可勾选）：

- [ ] 冷启动登录、断网 / 弱网提示
- [ ] 对话 → 生成计划 → 查看周计划与卡片
- [ ] 文本资料 / PDF（含偏大文件）出题
- [ ] 复习自评提交后间隔变化、今日数量正确
- [ ] 计划暂停后不进复习；恢复后回来；归档列表；删除确认
- [ ] 报告数据与近 7 日柱状；分享得次数日限
- [ ] 另一账号点分享链接：受邀欢迎额度（一生一次）
- [ ] 空状态 / 加载中 / 失败重试文案是否清晰

体验向可做的小完善（非商业功能）：

- 文案与引导（首页空计划、对话「正在思考」）
- 云函数超时 / 内存（`chat` / `generatePlan` / `material`）按实测再调
- `docs/review.md` 中低优先级项（到期查询、额度重置时区）按痛点择机修

相关文档：`docs/setup.md`、`docs/review.md`

---

### 阶段 B：对外运营 v1（最小可商业运营）

**目标**：能上架、能控成本、能提醒回来。

| 序号 | 事项 | 要点 | 参考 |
|------|------|------|------|
| B1 | 打开额度拦截 | `ENFORCE_QUOTA: true`，同步 common 后重部署 | `docs/m2-setup.md` |
| B2 | 恢复「我的」额度 / 广告 UI | 展示剩余次数、看广告领次数 | `m2-setup.md`、历史隐藏 UI |
| B3 | 配置激励广告 | 真实 `AD_UNIT_ID`；去掉依赖「直接领取」上线路径 | `utils/constants.js` |
| B4 | 订阅消息上线 | 模板 ID、`sendRemind` 环境变量与定时触发器、授权入口 | `m2-setup.md` |
| B5 | 审核与合规物料 | 类目、简介截图、**用户协议 / 隐私政策**页 | 公众平台 |
| B6 | 基础监控 | 云函数错误告警；关注 AI 失败与额度异常 | 云开发控制台 |

**验收**：新用户能完成闭环；对话次数可耗尽并可广告/分享补充；开启提醒的用户能收到订阅（在授权次数内）。

### 阶段 C：完整商业版（能赚钱）

**目标**：会员付费成为主收入，广告为辅；额度与权益产品化。

#### C1. 会员与支付

建议档位（可按实测调整）：

| 权益 | 免费 | 会员（示例） |
|------|------|--------------|
| 每日对话 | 20 | 更高或不限 |
| 每日生成计划 | 10（`MAX_PLAN_GEN_PER_DAY`） | 更高 |
| 资料 / 大 PDF | 基础 | 更大体积 / 更多次数 |
| 广告 | 可看广告换次数 | 去广告 |
| 报告 / 导出 | 基础 | 可增强（可选） |

实现要点（设计约束）：

- 微信支付：订单表（如 `orders`）、支付回调云函数、**服务端验签**，前端只传商品档位不传金额覆盖
- `users` 增加 `vipExpireAt` / `vipLevel`；所有额度判断统一走 `common/quota.js`（或 `common/vip.js`）
- 身份仍只信任 `OPENID`；购买结果以支付回调为准

#### C2. 额度体系产品化

- 对话、生成计划、资料出题可分项计数（避免一种行为耗尽全部体验）
- 会员 / 广告 / 分享奖励写入同一套原子更新（已有 `_.inc` 模式可复用）
- 前端「我的」清晰展示：剩余次数、会员到期、今日分享/广告剩余次数

#### C3. 分享裂变加固

- 邀请码替代裸 `_id`（可选）
- 分享海报（canvas）提升打开率（可选）
- 继续依赖日限 + 邀请一生一次；视刷量情况加设备/频次风控

#### C4. 运营最小集

- 意见反馈入口（表单写库或客服会话）
- 常见问题页
- 简易数据：DAU、次日留存、人均复习、付费转化（导出或看板均可）

**验收**：可完成一次真实支付开通会员；权益即时生效；免费用户路径不被破坏。

---

### 阶段 D：成熟壁垒版（差异化，按反馈排期）

按用户真实抱怨优先级做，不必一次做完。

| 方向 | 功能 | 价值 |
|------|------|------|
| 资料 | Word / PPT；扫描 PDF OCR；超大文件异步任务 | 扩大内容入口 |
| 复习 | AI 简答判分；错题本；按计划复习 | 提高复习质量 |
| 会话 | 多会话历史列表与切换 | 长期用户刚需 |
| 计划 | 完成度、周目标达成提示 | 增强成就感 |
| 召回 | 连续中断提醒、周末复盘（订阅次数内） | 留存 |
| 冷启动 | 求职/考证引导问卷 | 降低空白对话框流失 |
| 工程 | `loadDueCards` 库端过滤；额度重置统一东八区；关键路径冒烟 | 规模化稳定 |

## 5. 商业模式建议（简版）

| 收入 | 机制 | 现状 |
|------|------|------|
| 激励广告 | 看完广告 + 日限领对话次数 | 代码有，待开 M2 + 配广告位 |
| 分享裂变 | 分享领次数 + 邀请双向奖励 | 已上线骨架 |
| 会员订阅 | 去广告 + 更高额度 + 资料权益 | **待开发** |
| （可选）单次加油包 | 一次性加次数 | 可在会员后做 |

成本侧：AI Token、云函数、云存储、短信/无不涉及。**必须**靠额度 + 计划生成上限 +（上线后）会员控本；相关开关见 `ENFORCE_QUOTA`、`MAX_PLAN_GEN_PER_DAY`。

## 8. 工程与发布纪律（后续开发仍遵守）

1. 安全：身份只来自 `OPENID`；读写计划/卡片校验归属；密钥不进前端/仓库  
2. 复用：只改 `cloudfunctions/common`，禁止手改各函数内 `common/` 副本  
3. 数据：会话追加限长；奖励/额度用原子更新；删除计划连带卡片/资料  
4. 接口：前端只走 `api.js`；错误码集中；不吞异常  
5. 部署：`node scripts/install-functions.js` → 上传云函数 → 真机回归主闭环  

审查与已知低优先级债：`docs/review.md`。

## 9. 推荐推进顺序（回顾时用）

```
当前 ──► 阶段 A：测试体验、修文案与稳定性
       ──► 阶段 B：开 M2 + 广告 + 订阅 + 协议隐私 + 上架
       ──► 阶段 C：会员支付 + 额度产品化 + 反馈/简单数据
       ──► 阶段 D：按用户反馈做 OCR / 判分 / 多会话等
```

**不要跳过 B 直接做一堆 D**：没有额度与监控时，AI 成本与留存都不可控。

## 11. 当前阶段结论

- **前期要求的主闭环已完成**，可进入测试与体验完善。  
- **完整商业版尚未完成**：缺「打开并运营 M2」、缺「会员支付」、缺运营合规与深度体验能力。  
- 后续开发以本文阶段 B → C → D 为序；阶段 A 的问题与想法可记在本仓库 Issue / 备忘，再排期实现。
